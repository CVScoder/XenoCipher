1. Introduction to NTRU

What is NTRU?

  • NTRU (Nth degree TRUncated polynomial ring) is a lattice-based public key cryptosystem
  • Created by Joseph Silverman, Jeffery Hoffstein, and Jill Pipher in 1996
  • Released into the public domain in 2013
  • One of the leading candidates for post-quantum cryptography
Historical Note: NTRU was initially developed as a commercial product by NTRU Cryptosystems, Inc., before being released to the public domain.

Why NTRU Matters

  • Quantum-resistant: Secure against attacks from quantum computers
  • Efficient: Faster than RSA and ECC for comparable security levels
  • Versatile: Suitable for encryption and digital signatures
  • Practical: Implementable on constrained devices
Key Advantage: While RSA and ECC can be broken by quantum computers using Shor's algorithm, NTRU's security is based on lattice problems that are believed to be resistant to quantum attacks.

2. Mathematical Foundation

Polynomial Rings

NTRU operates in a truncated polynomial ring:

  • Ring: R = Z[X]/(XN - 1)
  • Operations are performed modulo XN - 1
  • Polynomials have degree at most N-1
f(x) = a₀ + a₁x + a₂x² + ... + aₙ₋₁xⁿ⁻¹

Where:
- Each coefficient aᵢ is an integer
- Operations are performed modulo p or q
- Polynomial multiplication is performed modulo (xⁿ - 1)

Key Parameters

  • N: Polynomial degree (determines security level)
  • p: Small modulus (typically 3)
  • q: Large modulus (typically power of 2)
  • d: Number of coefficients set to 1 in certain polynomials

Modular Arithmetic

Operations performed modulo p and q:

  • For polynomials a and b:
    • a + b (mod q): Add coefficients modulo q
    • a * b (mod q): Multiply polynomials, reduce coefficients modulo q
// Example of polynomial multiplication in truncated ring void NTRU::poly_mult(const Poly& a, const Poly& b, Poly& res) { std::fill(res.coeffs.begin(), res.coeffs.end(), 0); for (int i = 0; i < NTRU_N; ++i) { for (int j = 0; j < NTRU_N; ++j) { int idx = (i + j) % NTRU_N; // Reduction modulo X^N - 1 res.coeffs[idx] += a.coeffs[i] * b.coeffs[j]; } } res.mod(NTRU_Q); // Coefficient reduction modulo q }

3. NTRU Algorithm

Key Generation

  1. Choose random "small" polynomials f and g
  2. Compute inverses:
    • fp: inverse of f modulo p
    • fq: inverse of f modulo q
  3. Calculate public key: h = p * fq * g (mod q)
  4. Private key: (f, fp)
  5. Public key: h
void NTRU::generate_keys(NTRUKeyPair& kp) { Poly g; random_ternary(kp.f, NTRU_D); random_ternary(g, NTRU_D); Poly f_inv; poly_inv(kp.f, f_inv, NTRU_Q); poly_mult(g, f_inv, kp.h); for (int i = 0; i < NTRU_N; ++i) kp.h.coeffs[i] = (NTRU_P * kp.h.coeffs[i]) % NTRU_Q; } 
Key Generation Process:

1. Generate random small polynomials f and g
   f = -1 + X + X² - X⁴ + X⁶ + X⁹ - X¹⁰
   g = -1 + X + X² + X³ - X⁸ - X¹⁰

2. Compute inverses f⁻¹ mod p and f⁻¹ mod q
   f_p = 1 + 2X + 2X³ + 2X⁴ + X⁵ + 2X⁷ + X⁸ + 2X⁹
   f_q = 5 + 9X + 6X² + 16X³ + 4X⁴ + 15X⁵ + 16X⁶ + 22X⁷ + 20X⁸ + 18X⁹ + 30X¹⁰

3. Calculate public key h = p·f_q·g mod q
   h = 18 + 6X + 21X² + 16X³ + 2X⁴ + 21X⁵ + X⁶ + 17X⁷ + 30X⁸ + 3X⁹ + 25X¹⁰

Encryption

  1. Convert message to polynomial m with coefficients modulo p
  2. Choose random "small" polynomial r
  3. Compute ciphertext: e = r * h + m (mod q)
void NTRU::encrypt(const Poly& m, const Poly& h, Poly& e) { Poly r; random_ternary(r, NTRU_D); poly_mult(r, h, e); for (int i = 0; i < NTRU_N; ++i) e.coeffs[i] = (e.coeffs[i] + m.coeffs[i]) % NTRU_Q; }

Decryption

  1. Compute a = f * e (mod q)
  2. Compute b = a (mod p)
  3. Recover message: m = fp * b (mod p)
void NTRU::decrypt(const Poly& e, const Poly& f, Poly& m) { Poly a; poly_mult(e, f, a); for (int i = 0; i < NTRU_N; ++i) m.coeffs[i] = a.coeffs[i] % NTRU_P; }

Why Decryption Works

Starting with e = r * h + m (mod q)

Substitute h = p * fq * g:

e = r * (p * fq * g) + m (mod q)

Multiply by f:

f * e = f * r * p * fq * g + f * m (mod q)

Since f * fq = 1 (mod q):

f * e = p * r * g + f * m (mod q)

When we take modulo p:

f * e (mod p) = f * m (mod p)

Multiply by fp:

fp * f * e (mod p) = fp * f * m (mod p) = m (mod p)

5. Security Considerations

Security Strength

  • Security based on the hardness of Shortest Vector Problem (SVP) in lattices
  • Quantum-resistant: No known efficient quantum algorithm for SVP
  • Security level depends on parameter selection (N, p, q)
Lattice Problems:

Shortest Vector Problem (SVP):
  Find the shortest non-zero vector in a lattice

Closest Vector Problem (CVP):
  Find the closest lattice point to a given point

NTRU security relies on the hardness of these problems

Parameter Selection

Parameter Set N p q Security Level
NTRU-251 251 3 128 Moderate (~80 bits)
NTRU-439 439 3 2048 High (~128 bits)
NTRU-743 743 3 2048 Very High (~256 bits)

Known Attacks

  • Lattice-based attacks: Using lattice reduction algorithms like LLL or BKZ
  • Meet-in-the-middle attacks: Targeting the structure of the private key
  • Hybrid attacks: Combining lattice reduction with meet-in-the-middle techniques
Security Warning: The placeholder implementation of poly_inv() in the provided code is not secure and should be replaced with a proper implementation for production use.

Decryption Failure Rate

NTRU can experience decryption failures when parameters are not chosen carefully:

  • Occurs when coefficients of p*r*g + f*m exceed q/2
  • Probability depends on parameter selection
  • Modern NTRU implementations use parameters that make failures negligibly rare
